    2. Rewrite apps/tui/src/main.rs following the research-provided async pattern:

    a) Replace imports: remove manual `crossterm::{execute, terminal::*}` imports. Add `use futures::{FutureExt, StreamExt}; use crossterm::event::{EventStream, KeyEventKind};`. Use `ratatui::crossterm::event::{Event, KeyCode}` re-exports (avoid version conflicts per research pitfall 3). Keep `ratatui::DefaultTerminal` for the terminal type.

    b) Replace `fn main()` with:
    ```rust
    #[tokio::main]
    async fn main() -> anyhow::Result<()> {
        let mut terminal = ratatui::init();
        let result = run(&mut terminal).await;
        ratatui::restore();
        result
    }
    ```
    This replaces manual enable_raw_mode/EnterAlternateScreen/disable_raw_mode/LeaveAlternateScreen AND installs a panic hook automatically (STAB-06).

    c) Create `async fn run(terminal: &mut DefaultTerminal) -> anyhow::Result<()>` with:
    - Load AppState, create App
    - Create `EventStream::new()`
    - Create `tokio::time::interval(Duration::from_millis(250))` for tick timer
    - Main loop with `tokio::select!`:
      - Branch 1: `reader.next().fuse()` -- handle key events (filter `KeyEventKind::Press` per research pitfall about crossterm 0.28 sending Press+Release)
      - Branch 2: `tick_interval.tick()` -- empty body with comment "Future: refresh UI, poll background tasks"
    - Key handling: same as current (q=quit, Up/k=move_up, Down/j=move_down, Enter=run_status)

    d) Keep the App struct, Status enum, move_up/move_down/run_status methods, and the UI rendering closure (draw function) EXACTLY as they are. The only change is the event loop and terminal initialization.

    e) Important: the `ui` rendering logic should be extracted into a function `fn ui(frame: &mut ratatui::Frame, app: &mut App)` or kept as an inline closure in the draw call. Either approach is fine -- keep it simple.

    Do NOT change `run_git_status()` to async (per locked decision -- that's Phase 3).
    Do NOT use mpsc channels between event handler and main loop (over-engineering per research).
    Do NOT import `crossterm` event types directly -- use `ratatui::crossterm` or `crossterm::event::EventStream` (EventStream is not re-exported by ratatui).
